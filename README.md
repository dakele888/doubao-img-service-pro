# 豆包网页版生图 → 本地接口

把网页版豆包当成一个 OpenAI 兼容的 `/v1/images/generations` 接口，给魔哈工作台的「自定义生图接口」用。

```
魔哈 → http://127.0.0.1:8788/v1/images/generations
     → 本服务 → ego-browser 驱动豆包页面
     → 点「图像生成」→ 填提示词 → 发送 → 轮询抓图
     → 下载到缓存目录 → 返回图片地址
```

界面是**程序自己的窗口**（Win32 外壳 + WebView2 渲染），双击就出，不需要浏览器、不需要记地址。**整个程序只有一个 exe（约 700 KB），不带任何外部 DLL。**

## 快速开始

1. 确保 **ego lite 已打开**，里面的 `doubao.com` 是登录状态
2. 双击 `豆包生图服务.exe`，程序自己的窗口直接弹出来（不是浏览器，没有地址栏）
3. 点面板的 **×** 不是退出，而是**收进系统托盘，服务继续运行**；再双击托盘图标（或再双击一次 exe）就能把面板叫回来。要真正停止服务，右键托盘图标 → 退出

程序是 **Rust 编译的**，不依赖 Node / .NET；**目录里只有 `豆包生图服务.exe` 一个文件**。WebView2 的加载器（158 KB）已经编进 exe 里，首次运行释放到 `.webview\rt\` 再加载 —— 程序目录本来就会建 `.webview\` 放 WebView2 的数据，所以**不会额外冒出 DLL，也不往 C 盘写任何东西**（除非 exe 放在不可写目录，才会退回 `%LOCALAPPDATA%`）。数据（`config.json`、`out\`、`service.log`、`.webview\`）全在 exe 同目录。

## 启动验证（免责声明 + 密码）

每次启动先弹一个验证窗，两件事：

1. **免责声明** —— 必须勾选「我已阅读并同意」才能继续，不勾会提示；文字区可以滚动查看。
2. **启动密码** —— 默认开启，密码 `3.1415926`。输错红字提示、清空重输。

**验证不通过，服务连端口都不会监听**，所以别人拿到 exe 也调不了接口。

### 关掉 / 重新开启启动密码

面板**右上角**有个胶囊按钮 `启动密码 · 开`，点一下切到 `· 关`，写入 `config.json` 的 `requirePassword`，**下次启动生效**。关掉后启动只显示免责声明，点「同意并继续」直接进面板。

注意：关掉后，本机任何能访问 `127.0.0.1:8788` 的程序都能操作面板；不关则每次启动都要过密码。

### 换密码

密码只存**加盐 MD5**，exe 里搜不到明文。改 `src/auth.rs` 的 `PWD_HASH`，用这条命令算出新值（把最后的 `新密码` 换掉）：

```bash
node -e "const c=require('crypto');console.log(c.createHash('md5').update('doubao-img-v1:'+process.argv[1]).digest('hex'))" 新密码
```

然后 `cargo build --release` 重新编译即可。`SALT` 也可以一起改，改了记得同步命令里的盐。

## 托盘与常驻

窗口只是面板，服务本身不需要窗口。关掉面板服务照样跑，魔哈随时能调。

| 操作 | 结果 |
| --- | --- |
| 点面板 **×** | 收进系统托盘，**服务继续运行** |
| 点面板 **─** | 普通最小化到任务栏 |
| 双击托盘图标 | 打开面板 |
| 右键托盘图标 | 打开面板 / 打开缓存目录 / **退出（真正停止服务）** |
| 托盘图标找不到 | 多半被折叠进任务栏右下角的 **∧** 里（Win10/11 对新图标默认这样），拖到任务栏上就固定了 |

首次收进托盘会弹一个气泡提示。开机自启：把 exe 的快捷方式放进 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`。

退出流程走的是同一个 `quit_app`：先删托盘图标，再关 WebView2 控制器，最后销毁窗口，`service.log` 里不会留孤儿进程。

## 换一台电脑 / 发给别人用

**不是拷个 exe 就能用**。exe 本身只有 697KB，真正操作豆包的是 `ego-browser`，它属于 **ego lite**（装了 597MB，一份 Chromium）。所以目标机必须补齐三样：

| 需要的东西 | 体积 | 说明 |
| --- | --- | --- |
| 本 exe | **697 KB** | 就这一个文件，Rust 编译，不依赖 Node / .NET / VC 运行库 / 外部 DLL |
| **ego lite** | ~597 MB | 必须装。装完 `ego-browser` 才会出现，它是全流程的浏览器驱动 |
| **豆包登录** | — | 在 ego 浏览器里打开 `doubao.com` 扫码登录，不登录什么也生成不了 |
| WebView2 运行时 | 系统自带 | Windows 10/11 装了 Edge 就有，界面靠它渲染；缺了会自动退回浏览器窗口 |
| 魔哈工作台 | — | 调用方，不是本服务的依赖 |

### 步骤

1. 目标机装 ego lite，登录豆包，随便发一条消息确认能用
2. 把 `豆包生图服务.exe` 拷过去（单独一个 exe 就够，不用带 config.json / out）
3. 双击 exe，面板会自己弹出来
4. 面板「状态」里看 **ego** 是否为绿色「可用」；是红色「未找到」就点右边「检测」重试，或把 `ego-browser.exe` 的完整路径填进输入框再点「检测」
5. 魔哈里 Base URL 填 `http://127.0.0.1:8788/v1`，先手动跑一张验证

### 会自动处理的事

| 情况 | 行为 |
| --- | --- |
| 找不到 ego-browser | 依次找配置项 → `%LOCALAPPDATA%\.local\share\ego\active_version_dir` → `%ProgramFiles%\Citro Labs\ego lite\Application\*\` → PATH，不要求手动配 PATH |
| 豆包没登录 | 立刻返回 401 并提示「请在 ego 浏览器里登录」，不会干等 4 分钟才超时 |
| 拷了别人的 config.json | 对话地址那栏只是个展示，实际靠对话名重新找；找不到同名对话就新建一条，自愈 |
| 缓存目录 | 默认在 exe 同目录 `out\`，自动创建；换目录在面板改 |

**建议不要拷 `config.json` 和 `out\`**，新机器上让它自己长出来更干净（`config.json` 里可能残留上一个账号的对话名）。

**发给别人只需要一个 exe。** 使用说明内置在面板右上角的「部署帮助」按钮里（点开是弹层，四个可折叠区块：第一次用 / 接到魔哈里 / 常见问题 / 工作原理与限制），对方双击就能看到，不用另附文档。直接访问 `http://127.0.0.1:8788/#help` 也会自动打开这个弹层。

## 管理面板

双击 exe 直接弹出程序窗口。里面三块 + 一个按钮（内容由 WebView2 渲染，是 HTML 页面，但页面内容直接注入内存，**不经过任何地址**）：

| 区块 | 能做什么 |
| --- | --- |
| **部署帮助**（右上角按钮） | 弹层形式的完整使用说明：三步装好、接到魔哈、常见问题、工作原理与限制 |
| 状态 | 缓存目录、已缓存张数与占用、**ego 路径与可用性**（可手动指定）、实时队列；一键复制 Base URL |
| 顶部按钮 | **启动密码开关**（开/关，点一下切换）、**ego 官网**（用默认浏览器打开官方文档）、部署帮助 |
| 对话 | 改专用对话名（默认「生图专用」）；看当前对话地址；「解绑」= 下次重新找 |
| 缓存 | 改缓存目录、最多保留张数、最大占用 MB、保留天数；立即清理；清空全部 |
| 已缓存图片 | 缩略图列表，单张删除 |

## 固定对话「生图专用」

每次生成前会先在侧栏找名字等于「生图专用」的对话：

| 情况 | 行为 |
| --- | --- |
| 找到了 | 直接进这条对话，所有图都落在里面 |
| 没有 | 新开一条对话生成，**生成完自动把这条对话改名为「生图专用」** |

所以第一次跑完，侧栏就会多出一条叫「生图专用」的对话，之后一直复用它，不会再碎片化。
前提是**侧栏处于展开状态**（收起了就读不到列表）。改名靠的是对话项右侧「⋯ → 重命名」，页面改版会失效，日志会打「重命名失败，下次再试」。

想换新对话：面板上点「解绑」，再改个名字（比如「生图专用2」）。

## 缓存策略

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 缓存目录 | 空 = `程序目录\out` | 可填绝对路径，如 `D:\img-cache`，保存时自动建目录 |
| 最多保留 | 200 张 | 0 = 不限 |
| 最大占用 | 2048 MB | 0 = 不限 |
| 保留天数 | 0（不限） | 超过天数的先删 |

每次生成**下载完成后自动清理**，顺序是：先按天数删，再按张数删，最后按体积删，都是**从最旧的开始**。面板「立即清理」等于手动跑一遍。

## 魔哈里怎么填

生图设置 → 提供商选「自定义生图接口」：

| 字段 | 值 |
| --- | --- |
| Base URL | `http://127.0.0.1:8788/v1` |
| API Key | 随便填（不校验） |
| 模型名 | 随便填（忽略） |
| 并发数 | **1**（填大了也不会错，见下） |

### 多并发怎么处理的

豆包侧只有一个页签，两个请求同时操作同一个输入框必然串图，所以服务内部是**严格串行队列**：

```
请求 1 ──► 生成(约 22s) ──► 返回
请求 2 ── 排队等待 ────────► 生成 ──► 返回
请求 3 ── 排队等待 ─────────────► 生成 ──► 返回
```

| 项目 | 行为 |
| --- | --- |
| 魔哈里并发数 | 填几都行。服务按到达顺序排队，一个一个喂给浏览器 |
| 排队上限 | 30 个（`DOUBAO_IMG_QUEUE` 可调），超了返回 **429** |
| 排队超时 | 单个请求最多等 30 分钟（`DOUBAO_IMG_QUEUE_WAIT`，毫秒），超了返回 **504** |
| 吞吐 | 约 **2.7 张/分钟**（单张 18~26s），跟请求多少路无关 |
| 串图风险 | 无。实测 2/3 路并发，每张 URL 唯一，图内容与提示词一一对应 |

面板「状态」下面会实时显示 `生成中 #12 · 8s · 提示词… / 排队 3 个 / 成功 12 · 失败 0`，等得不耐烦能直接看出来。

**建议还是填 1**。填 5 的时候最后一张要等约 110 秒，魔哈那边的 HTTP 客户端可能先超时（超时后图仍然会生成完并留在缓存里，只是那次调用拿不到结果）。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/v1/images/generations` | `{prompt, n}` → `{data:[{url}]}`，`response_format=b64_json` 时附 base64 |
| GET | `/` | 管理面板 |
| GET | `/health` | 健康检查 |
| GET | `/api/config` | 配置 + 缓存统计 + 图片列表 + 队列快照 |
| GET | `/api/queue` | 队列状态：`running` / `waiting` / `done` / `fail` / `lastCost` |
| POST | `/api/config` | 改配置（`conversationName` / `conversationUrl` / `outDir` / `maxFiles` / `maxMB` / `keepDays`） |
| GET | `/api/images` | 图片列表 |
| POST | `/api/delete` | `{name}` 删单张 |
| POST | `/api/cleanup` | 按策略清理 |
| POST | `/api/clear` | 清空全部 |
| POST | `/api/reveal` | 打开缓存目录 |
| GET | `/files/<name>` | 取图 |

端口固定 `8788`（监听 `127.0.0.1`，仅本机可访问）。排队上限 30、单张生成超时 240 秒、排队等待上限 30 分钟，都是 `src/main.rs` 顶部的常量，要改直接改那里重新编译。

## 源码与构建

```bash
cargo build --release
powershell -ExecutionPolicy Bypass -File build.ps1   # 编译 + 补图标 + 输出到 dist\
```

`build.ps1` 做的事就是：`cargo build --release` → 复制成 `dist\豆包生图服务.exe` → 用 `tools\rcedit-x64.exe` 嵌入 `icon.ico`。

| 文件 | 职责 |
| --- | --- |
| `src/main.rs` | HTTP 服务、路由、生成流程、单实例唤醒 |
| `src/ego.rs` | 拼 ego-browser 要跑的脚本（含未登录检测）、带超时执行 |
| `src/sched.rs` | 串行队列（Condvar 严格 FIFO） |
| `src/cfg.rs` | config.json 读写 |
| `src/util.rs` | 日志、下载（系统 curl）、缓存清理、ego 定位 |
| `src/webview.rs` | 原生窗口 + 托盘 + 内嵌加载器释放 |
| `src/auth.rs` | 启动验证窗（免责声明 + 密码） |
| `src/panel.html` | 管理面板，编译时 `include_str!` 进 exe |
| `assets/WebView2Loader.dll` | 158 KB，编译时 `include_bytes!` 进 exe |

依赖只有 `serde_json` / `md-5` 和 `windows` / `webview2-com`（纯头文件式绑定，不链外部 DLL）；下载图片走系统自带 `curl.exe`，所以不需要 OpenSSL / 微软运行库。编译参数是 `opt-level="z"` + `lto` + `panic=abort` + `strip`，所以 exe 只有 719 KB。

**编译前必须存在 `assets\WebView2Loader.dll`**（取自 webview2-com-sys 的 `x64/` 目录），它被编进 exe，运行时释放到程序目录 `.webview\rt\`（不可写才退回 `%LOCALAPPDATA%\doubao-img\runtime\`）再 `LoadLibrary` + `GetProcAddress` 动态调用。这样 exe 的导入表里没有任何 WebView2 DLL，拷到哪都能跑。

**工具链注意**：本机用 `x86_64-pc-windows-gnu`，缺 `ld.exe` 时靠 `.cargo\config.toml` 指定 `rust-lld`。这个文件含绝对路径，所以没进仓库，照 `.cargo\config.toml.example` 复制一份改成自己的路径即可。用 MSVC 工具链的话不需要它，但 `webview2-com-sys` 在 GNU 下要 `dlltool`（binutils 里的），缺了会报链接错误。

## 排错

| 现象 | 原因与处理 |
| --- | --- |
| 「进不到图像生成模式」 | 豆包页面改版，底部工具栏按钮文案变了；或页签不在聊天页 |
| 「等待超时，没抓到新生成的图片」 | 出图变慢 / 被限流；重试一次通常就好 |
| 每次都新建对话 | 侧栏被收起了，读不到列表；或改名失败（看日志） |
| `启动 ego-browser 失败` | ego lite 没装，或装到了非默认位置。面板「ego 环境」点「检测」，仍不行就把 `ego-browser.exe` 完整路径填进去 |
| 返回 401「豆包还没登录」 | 到 ego 浏览器里打开 `doubao.com` 扫码登录，然后重试 |
| 生成很慢 | 每张都要真开页面走一遍，正常 18~26 秒 |
| 想看详细日志 | exe 同目录的 `service.log`（超过 1MB 自动轮转为 `service.old.log`） |
| 窗口里一片空白 | WebView2 没初始化成功，看 `service.log`；多半是系统没装 WebView2 运行时（Win10/11 一般都有） |
| 提示面板没能自动打开 | 系统缺 WebView2 运行时，程序已退回浏览器窗口并给了地址 |

## 限制

- 出图带豆包水印（URL 里 `cgen_wm0` 是水印模板）
- 依赖网页结构，豆包改版就可能失效
- 是自动化操作个人账号，频率高了有风控风险，别当生产接口
- 服务串行执行，并发会排队
- **不能只拷 exe 到新电脑就用**，目标机必须先有 ego lite 和已登录的豆包（见上文「换一台电脑」）
