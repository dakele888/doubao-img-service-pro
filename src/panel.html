部署帮助
第一次用：三步跑起来
  1. 装 ego lite（https://lite.ego.app，选 Windows 版），装完在里面打开 doubao.com 扫码登录豆包，随便发一句话确认能回复。
  2. 把 豆包生图服务.exe 放进一个普通文件夹（比如 D:\豆包生图\）。别放桌面、别放 Program Files，那里写缓存没权限。
  3. 双击运行：先勾选免责声明，再输入启动密码（出厂密码见 README），面板才会弹出来。看上面「状态」里 ego 是不是绿色可用；红色就点「检测」，还不行把 ego-browser.exe 完整路径填进去。

不想每次输密码：面板「状态」里点「启动密码 → 关闭」，下次启动就只显示免责声明。
点面板右上角的 × 不是退出，而是收进系统托盘，服务继续运行，魔哈随时能调。要重新打开面板：双击托盘图标，或者再双击一次 exe。
托盘图标可能被折叠在任务栏右下角的 ∧ 里，可以拖出来固定。真正停止服务要在托盘图标上点右键 → 退出。

接到魔哈里

魔哈工作台 → 生图设置 → 提供商选「自定义生图接口」：

Base URLhttp://127.0.0.1:8788/v1
API Key随便填，比如 x（不校验）
模型名随便填，比如 doubao（忽略）
并发数1。填大了也不会串图，服务内部排队，但最后几张要等很久

填完先手动跑一张。第一张慢一点（约 30 秒），稳定后每张 18~26 秒，大约 2.7 张/分钟。

参考图（图生图）

豆包的参考图只能在输入框里粘贴进去，接口这边已经封装好了：调用时多带一个图片字段即可，服务会先把图粘进输入框，再发提示词。

图片地址{"prompt":"改成水彩风","image":"https://x.com/a.png"}
base64"image":"data:image/png;base64,iVBOR..."，也可以不带 data: 前缀
多张参考"images":["...","..."]，最多 3 张
别名image_url / init_image / reference_image / source_image 都认
限制单张 ≤ 8MB，只支持 PNG / JPEG / WEBP / GIF

不想写代码也行：把图存到本地，用 curl 调一次就能验证；/v1/images/edits 和 /v1/images/generations 都指向同一个处理流程。

常见问题
返回 401 豆包还没登录到 ego lite 里重新登录 doubao.com，再重试
启动 ego-browser 失败ego lite 没装，或装在非默认位置。按上面第三步填路径
进不到图像生成模式豆包页面改版了，看 service.log 后联系维护的人
等待超时，没抓到图豆包卡住或被限流，重试一次通常就好
双击没反应已经有一个实例在跑了，看任务栏有没有面板窗口
图片在哪exe 同目录的 out\，面板里也能直接打开

详细日志在 exe 同目录的 service.log，超过 1MB 自动轮转。

它是怎么工作的 / 有哪些限制

面板背后是个本机小服务：收到生图请求后，用 ego-browser 驱动你已登录的豆包页面，点「图像生成」、填提示词、回车，然后轮询抓新出现的图，下载到本地再返回地址。所以它完全走你自己的豆包账号，不需要任何 API Key。

出图带水印网页版豆包本身的水印，去不掉
依赖页面结构豆包改版就可能失效，需要更新脚本
别高频刷是自动化操作个人账号，太快有风控风险

要一直开机电脑睡眠或关机，服务就断了
